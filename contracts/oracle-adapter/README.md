# Roastake Oracle Adapter

NEAR Rust contract responsible for requesting OutLayer execution and storing validated coffee-index observations.

## Responsibilities

- Maintain an owner/authorized requester policy.
- Initiate `request_execution` on `outlayer.testnet` with `payer_account_id = Some(caller)` so normal execution refunds are sent directly to the caller by OutLayer.
- Track pending requests with unique nonces and market symbols.
- Receive a private callback and handle promise success/failure safely.
- Validate schema, timestamp, market, price bounds and replay protection.
- Store the latest valid fixed-point observation.

## Refund Solvency, Insurance Accounting, Claim Liveness & Storage Lifecycle (Missions 03C.3.6 – 03C.3.7.6)

- **Ambiguity of `PromiseError::Failed`:** In NEAR asynchronous execution, `PromiseError::Failed` in `on_outlayer_execution` does not distinguish between an initial receipt failure (where NEAR returns the attached deposit to this adapter) and a downstream failure after `outlayer.testnet` already accepted and retained the deposit.
- **UnreconciledFailure State:** On `PromiseError::Failed`, the adapter records an `UnreconciledFailure` (`unreconciled_failures`) and emits `execution_failed_unreconciled` without creating an unbacked payable `RefundCredit` or increasing `total_refund_liability`.
- **Explicit Storage Flush & Formal Solvency Invariant (`F-02`, `F-04`, `F-07`, `L-03`):** `RoastakeOracleAdapter` maintains **8** persistent `near_sdk::store` collections total: **1** uncached `LookupSet` (`authorized_requesters`) and **7** cached collections (`markets`, `prices`, `pending_requests`, `unreconciled_failures`, `pending_refunds`, `claims`, `insurance_compensations`). Before every solvency check (`assert_solvency_invariant()`), `flush_storage()` flushes all **7** cached collections so `env::storage_usage()` reflects exact persisted trie bytes:
  $$\text{spendable\_balance} \ge \text{minimum\_operating\_reserve} + \text{refund\_reserve\_balance} + \text{insurance\_reserve\_balance} + \text{insurance\_return\_pending} + \text{backed\_refund\_liability}$$
  where $\text{spendable\_balance} = \text{account\_balance} - (\text{storage\_usage} \times \text{storage\_byte\_cost})$ and $\text{backed\_refund\_liability} = \text{total\_refund\_liability} - \text{total\_in\_flight\_liability} - \text{total\_disputed\_liability}$.
  - Furthermore, `admin_designate_refund_reserve` enforces `compute_encumbered_backing_floor()` (`required_backing + total_in_flight_liability + total_disputed_liability + total_in_flight_insurance_liability + total_unresolved_insurance_liability`) so returning system refunds from failed transfers can never be designated as surplus before their callback or reconciliation runs.
  - **Accepted Liveness Limitation (`M-01`) & Operational Mitigation:** Because a NEAR contract cannot inspect historical receipts on-chain to distinguish a returning system refund from a failed transfer (`Callback missing`) from an unrelated requester's `InitialPanic` refund sharing the contract balance, any unacknowledged `Disputed` claim/compensation continues to raise `encumbered_backing_floor` (fail-closed) and can block `admin_designate_refund_reserve` for unrelated failures. **Concrete operational mitigation:** operators can use `#[payable] fund_refund_reserve()` with fresh NEAR and call `promote_unreconciled_refund(nonce)` directly (which checks `compute_required_backing()`, not `encumbered_backing_floor`) so unrelated requesters settle immediately without touching disputed liabilities.
  - Outbound transfers (`claim_refund`, `compensate_disputed_claim`) enforce pre-transfer `assert_solvency_invariant_with_outbound_transfer(amount_yocto)`. All execution/settlement callbacks (`on_outlayer_execution`, `on_refund_transfer` success, `on_insurance_transfer` success) enforce `assert_solvency_invariant()` post-flush, while failed-transfer callbacks transition to `ReturnPending` and enforce `assert_solvency_invariant()` inside `reconcile_returned_refund` / `reconcile_returned_insurance` once the asynchronous NEAR system-refund receipt lands.
- **Segregated Reserves & External Resolution State Machine (`L-02`):**
  - `fund_operating_reserve()` (`#[payable]`): adds attached NEAR directly to `minimum_operating_reserve` so contributed operating funds can never be reclassified via `admin_designate_refund_reserve`.
  - `fund_refund_reserve()` (`#[payable]`): adds newly attached NEAR directly to `refund_reserve_balance`.
  - `admin_designate_refund_reserve(amount, evidence_sha256)`: designates unencumbered spendable funds above the encumbered backing floor into `refund_reserve_balance` (administrative attestation, not on-chain cryptographic proof).
  - `promote_unreconciled_refund(nonce)`: rejects records with an active external-resolution proposal (`ERR_EXTERNAL_RESOLUTION_PROPOSED`), atomically consumes `refund_reserve_balance`, removes the `UnreconciledFailure`, and creates a 1:1 backed `RefundCredit`.
  - `admin_resolve_unreconciled_external(nonce, evidence_sha256)` sets `external_resolution_proposed = true` without deleting the record; the original requester may either confirm (`acknowledge_unreconciled_resolved_external(nonce)` -> terminal deletion) or dispute (`reject_unreconciled_external_resolution(nonce)` -> clears proposal so backed promotion remains unlocked); admins may also clear a stale proposal via `admin_cancel_unreconciled_external_resolution(nonce)` without deleting the failure or auto-creating a refund.
- **Terminal Claim Cleanup, `ReturnPending` Safety & Disputed Claim Liveness (`F-03`):**
  - Successful `on_refund_transfer` callbacks decrement `total_refund_liability` once and delete the terminal `RefundClaim` record from `claims` (`claims.remove(&claim_id)`), preventing permanent storage growth.
  - Failed payout transfers (`on_refund_transfer` observing `Err(...)` from the NEAR runtime) transition to `ClaimStatus::ReturnPending` / `RefundStatus::ReturnPending` (`return_pending_amount`), keeping the amount in `total_refund_liability` until `reconcile_returned_refund(claim_id)` verifies that the NEAR system-refund receipt has restored full backing under the solvency invariant.
  - When an `InFlight` claim is marked `Disputed` (`mark_claim_disputed` or `admin_reconcile_stuck_claim(..., ConfirmedFailure)` after `STUCK_CLAIM_MIN_AGE_BLOCKS = 100`), `credit.active_claim_id` is cleared (`None`) while the disputed amount stays quarantined in `credit.disputed_amount`. Subsequent independent promoted credits (`available_amount > 0`) remain independently claimable via `claim_refund()` under a new `claim_id` without ever paying or mutating historical `Disputed` claims.
- **Non-Destructive Stuck-Claim Governance & Insurance Lifecycle (`F-01`, `F-02`):**
  - Neither `admin_reconcile_stuck_claim(claim_id, ConfirmedSuccess)` nor `admin_propose_disputed_settlement(claim_id, evidence_sha256)` (available after `DISPUTE_RESOLUTION_DELAY_BLOCKS = 1,000`) can unilaterally delete a `Disputed` `RefundClaim` or reduce `total_refund_liability`; they record `admin_settlement_proposed = true` on the claim. Terminal zero-payout closure requires claimant acknowledgement (`acknowledge_disputed_transfer_received(claim_id)`) or a late objective `on_refund_transfer` callback.
  - **Separate Insurance Mechanism:** Disabled by default (`insurance_enabled == false`). `fund_insurance_reserve()` (`#[payable]`) maintains `insurance_reserve_balance` strictly isolated from `refund_reserve_balance` and pooled surplus. `compensate_disputed_claim` moves `amount` from `insurance_reserve_balance` into `total_in_flight_insurance_liability` (bounded by `max_active_insurance_compensations`, default **`32`**, hard cap `HARD_MAX_ACTIVE_INSURANCE_COMPENSATIONS = 100`).
  - **Missing Insurance Callback Recovery:** If `on_insurance_transfer` does not run after `STUCK_CLAIM_MIN_AGE_BLOCKS = 100`, `mark_insurance_compensation_disputed(compensation_id)` moves the record from `InFlight` (`total_in_flight_insurance_liability`) to `Disputed` (`total_unresolved_insurance_liability`) without restoring `insurance_reserve_balance`. A `Disputed` insurance compensation can be closed by a late `on_insurance_transfer` callback (`Ok` deletes record; `Err` moves to `ReturnPending` for `reconcile_returned_insurance`) or by recipient acknowledgement (`acknowledge_insurance_compensation_received(compensation_id)`).
- **Two-Step Admin Governance:** Single-step `set_admin` is disabled (`ERR_SINGLE_STEP_SET_ADMIN_DISABLED`). Admin rotation uses `propose_admin(new_admin)` + `accept_admin()` by `pending_admin` (or `cancel_admin_proposal()`). Production deployments should use a $\ge 2$-of-$3$ or $3$-of-$5$ multisig/DAO account as `admin`.
- **Storage Capacity Budget, String Bounds & Hard Caps (`L-03`, `F-07`):**
  - `compute_open_request_slots()` counts `pending_request_count + unreconciled_failure_count + max(active_refund_credit_count, active_claim_count)` against `max_open_requests` (default `100`, hard cap `HARD_MAX_OPEN_REQUESTS = 500`), retaining capacity slots until refund credits/claims reach terminal resolution. Hard caps also bound `HARD_MAX_ACTIVE_INSURANCE_COMPENSATIONS = 100`, `HARD_MAX_MARKETS = 32`, and `HARD_MAX_AUTHORIZED_REQUESTERS = 100`.
  - Storage margins are `OPEN_REQUEST_STORAGE_BUDGET_BYTES = 512`, `RECORD_STORAGE_MARGIN_BYTES = 512`, initial `STATE_STORAGE_MARGIN_BYTES = 512`, and incremental `STATE_GROWTH_MARGIN_BYTES = 128` (enforced in `propose_admin` and `set_outlayer_contract` to cover variable `AccountId` expansion persisted in `STATE` after method return).
  - UTF-8 byte limits bound `WorkerOutput.source <= 128` bytes, `WorkerOutput.data_class <= 32` bytes, and `MarketConfig` strings (`symbol <= 64`, `unit <= 16`, `description <= 256`, `wasm_url <= 256`, `build_target <= 32`), ensuring worst-case `PriceObservation` `IterableMap` insertion (`<= 493` bytes) stays within `OPEN_REQUEST_STORAGE_BUDGET_BYTES = 512`.
- **Fresh-Deployment Policy & Release-Candidate Artifact:** Built via `cargo-near 0.22.0` (`cargo near build non-reproducible-wasm --locked --no-abi`) into `integration-tests/near-sandbox-js/artifacts/roastake_oracle_adapter_release_candidate_m03376.wasm` (`378,335 bytes`, SHA-256 `a9a07710ed10133b36b503fe81185cd83a8bbc2179a3f17ce8f09cc94c3756b8`). Raw `cargo build --target wasm32-unknown-unknown --release` output (`target/wasm32-unknown-unknown/release/roastake_oracle_adapter.wasm`) is unoptimized and must never be deployed. Because no legacy ROASTAKE Oracle Adapter has been deployed on Testnet, **fresh deployment to a new Testnet account (`init`) is required**, and in-place WASM replacement over any legacy state is forbidden without an explicit migration method. Note that Sandbox integration tests exercise local `Mock OutLayer` contracts rather than live `outlayer.testnet`.
- **Stale Execution `request_id` Limitation:** `outlayer.testnet::cancel_stale_execution(request_id)` requires `predecessor_id == request.sender_id` (this adapter) after 600 seconds, but `request_execution` returns a yield promise rather than the OutLayer-internal `request_id` synchronously (`request_id` is only emitted in OutLayer logs). Autonomous on-chain cancellation therefore requires off-chain `request_id` indexing in a future iteration.

## Not in scope yet
